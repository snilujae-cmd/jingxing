# B 方案：三策略比较结果发布与读取

本文对应本次独立实施副本中的实际代码。系统发布的是已完成的科研情景仿真，不代表景区真实实时车辆、真实排队、官方实时调度或运营承诺。

## 1. 功能与文件范围

Admin 原有固定调度、动态阈值调度、滚动预测优化仍调用同一仿真引擎。B 方案新增公开比较摘要的发布、校验和读取层，让没有管理员登录状态的独立游客可以看到 Admin 已完成并成功发布的三策略指标和排队曲线。

| 文件 | 职责 |
| --- | --- |
| `comparison_data.py` | 从三个真实仿真结果构建比较摘要，校验共同参数、运行身份、指标及曲线 |
| `shared_run_store.py` | 同包原子发布所选策略的四份 CSV 和可选比较摘要；读取时处理兼容与降级 |
| `views/4_Admin_Smart_Dispatch.py` | 计算成功后发布结果，显示比较编号、运行编号和发布状态 |
| `views/user.py` | 只读显示已发布比较，保留单次仿真、线路查询、回放、趋势及刷新 |
| `tests/test_comparison_publishing.py` | B 方案发布、读取、权限与一致性测试 |

`core/simulation.py`、`core/optimizer.py`、`core/exporter.py`、`user_data_adapter.py` 的原计算和四份 CSV 契约没有因 B 方案改变。没有增加运行依赖。

## 2. 同一共享包中的内容

共享包默认位于项目内 `data/shared/current_run.zip`。可通过环境变量 `JINGXING_SHARED_RUN_PATH` 指定服务器上的其他路径；应用代码不依赖开发者电脑的绝对路径。

一次三策略比较成功发布后，共享 ZIP 内包含：

```text
current_run.zip
├── od_flow.csv
├── station_state.csv
├── vehicle_state.csv
├── passenger_results.csv
└── comparison.json
```

四份 CSV 全部来自管理员当次选中策略的同一次仿真，其 `run_id` 必须相同。`comparison.json` 包含该组全部三个策略的指标、真实排队快照聚合和共同参数，其 `selected_run_id` 必须等于这四份 CSV 的运行编号。

其他两种策略在公开包中保存指标和排队曲线摘要，不额外保存它们的四份详细 CSV。因此单次线路查询、逐车回放与单次趋势仍对应选中策略；三策略比较区负责展示同组摘要，不把三个策略的逐人或逐车数据混在一起。

`core.exporter.zip_content(result)` 及 Admin 的“下载4份联调CSV”继续输出原四份 CSV。共享发布层在该输出上附加 `comparison.json`，没有向原 CSV 增列、改名或修改字段值。测试逐字节比较了原导出与共享包中的四份 CSV。

## 3. 比较元数据契约

`comparison.json` 使用 UTF-8 JSON，当前版本为 1，最大未压缩大小为 2 MiB。JSON 中的数值必须有限，不接受 NaN 或无穷大。原有整体 ZIP 25 MiB、单份 CSV 12 MiB 的读取限制继续有效。

| 顶层字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema_version` | 整数 | 当前为 `1` |
| `comparison_id` | 字符串 | 以 `cmp-` 开头的确定性比较标识 |
| `published_at` | 字符串 | 构建发布元数据时的 UTC 时间，ISO 8601 格式，包含 `+00:00` 时区；界面可转换为北京时间显示 |
| `selected_run_id` | 字符串 | 本共享包中四份详细 CSV 对应的运行编号 |
| `seed` | 非负整数 | 三个策略共同使用的随机种子，独立于 `params` 保存 |
| `demand_signature` | 字符串 | 原仿真引擎返回的客流签名，用于核对同组客流 |
| `params` | 对象 | 原仿真引擎返回的完整归一化共同参数快照 |
| `strategies` | 数组 | 恰好三项，分别为 `fixed`、`dynamic`、`optimized` |

`params` 保存仿真实际使用的参数，而非读取当前页面上尚未重新运行的控件值。包括客流模式、到达率、时长、高峰倍数、潮汐与突发设置、A/B 车队、逐车容量、假设速度、固定间隔、队列阈值、停站与折返时长、最小发车间隔、优化器决策间隔、预测窗口、束宽、每次最大发车数、快照间隔和线路权重；保存场景带有的突发中心、宽度和强度也会保留。

三策略必须具有完全相同的完整参数、种子和客流签名。缺少策略、策略重复、运行编号重复、所选结果不属于比较组，或所选结果的指标、参数和曲线与比较组不符时，发布会被拒绝。

每项 `strategies` 的字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `strategy` | 字符串 | `fixed`、`dynamic` 或 `optimized` |
| `run_id` | 字符串 | 该策略对应的实际仿真运行编号 |
| `metrics` | 对象 | 以下原引擎指标，保留数值，不预先做页面显示四舍五入 |
| `queue_series` | 数组 | `[{"time_min": 数值, "waiting_total": 非负整数}, ...]` |

| `metrics` 字段 | 类型／单位 | 统计口径 |
| --- | --- | --- |
| `total_arrivals` | 整数／人 | 仿真期间全部到达人数 |
| `served` | 整数／人 | 仿真截止前已上车人数 |
| `completed` | 整数／人 | 已完成下车人数 |
| `onboard_end` | 整数／人 | 截止时仍在车上人数 |
| `unserved` | 整数／人 | 截止时仍未上车人数 |
| `total_departures` | 整数／趟 | 引擎实际发车次数 |
| `avg_wait` | 数值／分钟 | 已上车游客的平均候车时间 |
| `max_wait` | 数值／分钟 | 已上车游客的最长候车时间 |
| `p95_wait` | 数值／分钟 | 已上车游客候车时间的第95百分位 |
| `over_ratio` | 数值／0到1 | 已上车游客中候车超过15分钟的比例 |
| `service_rate` | 数值／0到1 | 已上车人数除以全部到达人数；无到达者时为0 |
| `avg_observed_wait_all` | 数值／分钟 | 全部到达游客的观测候车均值，未上车者仅计至仿真结束 |
| `total_wait_person_min` | 数值／人分钟 | 全部到达游客按上述观测口径累计的候车人分钟 |
| `vehicle_busy_minutes` | 数值／车分钟 | 引擎统计的车辆忙碌时间合计 |

`queue_series` 直接将对应策略的真实 `station_state` 按 `time_min` 汇总 `queue_length`，不生成估计轨迹。三个策略快照时刻必须相同、严格递增，并位于仿真时长范围内；三个策略的到达总人数也必须相同。

`comparison_id` 取规范化比较内容的 SHA-256 前16个十六进制字符，计算时排除 `comparison_id` 和 `published_at`。因此相同输入、相同结果和相同选中策略得到相同比较编号，重复发布时间可以不同。该标识用于检查意外损坏或内容变化，**不是数字签名、身份认证或防伪证明**。发布权限由原有管理员验证负责；服务器文件及管理员账户仍须由部署方妥善管理。

## 4. API、权限与兼容

```python
publish_result(result, path=None, comparison_results=None)
load_shared_bundle(stations, path=None)
load_shared_run(stations, path=None)
```

`publish_result` 首先执行原有 `assert_admin()`，验证成功后才构建元数据、导出或创建目录。现有 `publish_result(result)` 和 `publish_result(result, path)` 调用继续有效，返回值仍是写入路径 `Path`。

传入 `comparison_results` 时必须提供三个真实结果。省略该参数表示只发布单次仿真，最终 ZIP 中不包含比较元数据。比较发布不会向游客开放后台设置、仿真执行或写入权限；游客读取无需继承管理员会话。

`load_shared_bundle` 一次读取共享 ZIP 的完整字节快照，返回 `SharedBundle`：

| 属性 | 结果 |
| --- | --- |
| `run` | 原 `RunData` 对象；共享包尚不存在时为 `None` |
| `comparison` | 校验通过的比较字典；没有比较或比较无效时为 `None` |
| `comparison_error` | 比较元数据无效时的说明；正常无比较时为 `None` |

旧 `load_shared_run` 继续返回单个 `RunData` 或 `None`，内部复用同一次读取逻辑。旧共享包只含四份 CSV 时可以正常读取，不要求补造 `comparison.json`。

## 5. 发布替换与错误处理

发布先在目标所在目录写临时文件，写完刷新并同步，再使用 `os.replace` 整体替换共享包。读取端因此获得某一次完整发布，不逐文件拼接不同运行的 CSV 或比较结果。

发布参数校验失败，或写入、原子替换失败时，不会用不完整结果覆盖上一份成功共享包；临时文件会清理。首次发布失败时仍然没有共享结果。页面会提示本会话仿真已完成但共享发布失败，独立游客可能继续读到旧结果。

**再次运行并发布单次策略，会整体替换共享包并清除旧比较。** 这是当前行为，用于避免新单次 CSV 与旧比较被一起展示。若需要游客重新看到三策略，请重新完成并成功发布同场景三策略比较。

读取时先校验原四份 CSV。它们本身无效或缺失时，原有读取错误继续向页面报告，不把基础数据错误静默当成有效仿真。只有可选比较元数据的问题才降级：

- JSON 无效、格式版本不支持、字段缺少、非有限数值、校验标识不符或运行编号不符时，保留有效单次仿真。
- 比较文件重复、过大、压缩数据损坏、带加密标记或压缩方式不支持时，保留有效单次仿真。
- 比较元数据虽可解析，但选中策略的乘客数量、候车指标或排队曲线与实际 CSV 不一致时，保留有效单次仿真并隐藏比较。

所选策略的乘客数量、平均／最大／P95 候车、超过15分钟比例、全体观测均值与总候车人分钟均从 CSV 重算核对。导出乘客时刻与候车值为5位小数，因此核对使用已知舍入容差；15分钟比例对阈值附近的舍入作范围核对。所选策略的排队曲线必须与 CSV 汇总一致。发车次数和车辆忙碌时间不能由这四份快照 CSV 完整精确反推，保留原引擎输出，并由发布时同组、同运行校验保护。

## 6. 独立游客使用及部署限制

管理员在“智能调度”完成“同场景比较三策略”后，原有选中策略结果与本组三策略比较会一起尝试自动发布。Admin 页面显示的是本会话上次发布状态；其他管理员随后运行或发布时，服务器最新包可能变化。

游客打开同一服务器上的 User 页面，选择“最新共享仿真”，点击“刷新共享结果”，即可读取最新成功发布的完整包。核对比较编号、关联单次运行编号和各策略运行编号，可确认正在展示哪次结果。刷新只读取，不会触发仿真。内置演示样例及原“下载4份联调CSV”上传方式保留单次仿真功能，不带已发布比较。

当前共享存储是单台 Streamlit 服务的本地文件。不同浏览器、不同设备只有连接到同一服务实例或同一实际共享存储时，才会读取到同一包。应用睡眠、重启、重建或重新部署后，本地共享文件可能丢失；它不是长期归档或数据库，评审演示前需检查并视情况重新发布。

多实例分别使用各自本地磁盘时，不保证读到相同比较结果。需要所有实例挂载同一可写持久目录并配置 `JINGXING_SHARED_RUN_PATH`，同时确认该文件系统支持所需的整体替换语义；也可另行设计数据库或对象存储后端。当前版本没有引入该类外部服务或迁移机制。多个管理员并发发布时，最后一次成功替换决定游客看到的当前共享包，当前实现不保存发布历史。
